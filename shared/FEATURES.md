# 機能の対応状況

TortoiseGit の[日常操作ガイド](https://tortoisegit.org/docs/tortoisegit/tgit-dug.html)を比較対象としています。GitNebula は完全互換ではありません。macOS / Windows のホーム、常駐、Stash と履歴編集に対応しています。対応範囲は下表を参照してください。

| 操作 | macOS | Windows | Linux |
| --- | --- | --- | --- |

## 制限

- 対話的 Rebase（コミット並べ替え・Squash）、Amend、履歴からの複数コミット選択、部分的な行のステージは未対応です。
- ファイルの状態を示す Finder / Explorer のオーバーレイアイコンは未対応です。アプリと Finder メニューにはアイコンがあります。
- 外部 Diff / Merge ツールの設定 UI、Git LFS、Bisect、Reflog からの専用復元 UI は未対応です。
- Worktree の削除、Submodule の削除・ブランチ追跡設定、メール形式パッチの連続適用は未対応です。
- Pull は fast-forward のみです。強制 Push、リモートブランチ・タグの削除 UI はありません。
- HTTPS 認証には Git credential helper を使います。SSH は詳細設定で指定した秘密鍵、または既存の SSH 設定・agent を使います。

## macOS の操作場所

通常起動はメニューバーのアイコンのみで、Dock とウィンドウは表示しません。常駐メニューは「GitNebula を開く」・詳細設定・起動オプション・終了です。アプリ画面には詳細設定への入口だけを表示します。Git 操作は Finder の右クリックから対象フォルダ付きで開きます。操作画面のパス欄は直接入力・貼り付け・参照ができます。起動オプションにはログイン時自動起動と、起動時のアプリ画面表示（初期値オフ）があります。

Stash、タグ、リモート設定にはそれぞれ専用の画面があります。履歴編集・比較・Blame・パッチ・Worktree・Submodule は「その他の機能」から専用画面へ進みます。ブランチ作成や Merge は「リポジトリの管理 → ブランチの管理」、Stage・Unstage・Ignore・変更破棄は「リポジトリの管理 → 作業ファイルの管理」です。競合解決とコミット作成者の設定も独立した画面です。差分一覧・履歴・コミットに本文比較を埋め込まず、ファイルを開いて比較へ進み、「戻る」で一覧と下書きを維持します。

Rebase / Cherry-pick / Revert が競合した場合は、案内の「競合の解決を開く」から専用画面に進み、解決して「再開」を押します。中止ボタンは競合解決の作業を破棄する前に確認を表示します。Stash の適用が競合した場合、退避データは残り、通常のコミットとして解決します。Apply / Pop はクリーンな作業ツリーで実行し、ステージ状態も復元します。

macOS / Windows のメニューには Cherry-pick、Revert、Rebase と競合解決の入口があります。Cherry-pick / Revert は専用画面のコミット一覧から、Rebase は専用画面のブランチ一覧から対象を選びます。Windows の Stash の保存・適用ボタンは、初回コミット、未追跡ファイルのチェック、選択、未コミット変更、競合の状態に応じて有効になります。

アプリ画面は GitNebula の表示と詳細設定への入口だけとし、リポジトリ選択・Clone・Init・最近の履歴を置きません。Git 操作は対象フォルダの右クリックから開き、変更・履歴・ブランチ・リモート・リポジトリの順で区切ります。

詳細設定の SSH 認証で秘密鍵と鍵のパスフレーズを保存できます。パスフレーズは macOS キーチェーン / Windows 資格情報マネージャーに保存し、Clone・Fetch・Pull・Push の鍵解除に自動で使用します。秘密鍵パスを空欄にすると既存の SSH 設定と agent を使用し、パスフレーズ欄だけを空欄にすると保存済みの値を保持します。保存した値を削除するボタンがあります。接続先のホスト鍵は確認を表示します。
