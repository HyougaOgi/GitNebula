# GitNebula の操作とデザイン

GitNebula はファイルマネージャーから使う Git クライアント。
基本の流れは **右クリック → GitNebula → 操作 → 確認・実行 → 閉じる**。
アプリを開いてからリポジトリや操作を選び直す必要をなくす。

macOS は **一覧 → ファイル差分 → 戻る** の同一ウィンドウ内の遷移とする。通常起動・アプリの再表示ではメニューバーに常駐するだけで、Dock アイコンとウィンドウは表示しない。常駐メニューは「ようこそを開く」「詳細設定」「起動オプション」「終了」のみ。対象フォルダのない常駐メニューに Git 操作を並べない。起動オプションはログイン時自動起動と、起動時のようこそ表示（初期値オフ）。ようこそ画面でリポジトリを選択した後は「このリポジトリで操作する」から専用画面を開ける。Finder の右クリックでは選んだ操作を直接開く。差分一覧は状態・ステージ状態・相対パスの表のみ。単クリックは選択、ダブルクリック・Enter・「差分を開く」で1ファイルの比較専用画面へ進む。比較画面には一覧・編集・コミットなどの操作を混在させない。左右比較は行番号、色分け、行位置合わせ、同期スクロール、変更箇所への移動に対応する。

Cherry-pick / Revert はコミット一覧、説明、実行先ブランチ、確認・実行ボタンだけの専用画面を開く。Rebase / Merge はブランチ選択と確認・実行の専用画面を開く。これらの画面に作業ファイルの差分一覧を表示しない。ウィンドウ名は表示中の経路だけが更新し、保持中の画面にタイトルを書き換えさせない。

履歴画面はコミット一覧と説明・変更ファイル一覧を同じ画面に置く。コミット画面はチェック付き一覧・メッセージ・実行のみ。Stash／タグは各一覧と専用操作から変更ファイル一覧へ進む。戻ると選択・絞り込み・スクロール・下書きを維持する。各遷移の NSHostingView を保持し、表示中の画面だけを接続する。操作後は関連リポジトリの画面を更新し、残存する選択と入力を保持する。配色と星空の装飾は維持する。

macOS の「リポジトリの管理」は作業ファイル・ブランチ・競合解決・作成者設定への入口。「その他の機能」は各履歴操作・パッチ・Worktree・Submodule などの専用画面への入口。リモート設定に作成者設定を置かず、コミット画面に Stage / Unstage / Ignore / 変更破棄を置かない。競合時は案内から解決画面へ進む。

## 右クリックメニュー

共通の起動契約は以下のとおり。macOS の表示名・画面分割は上記に従い、他 OS の既存構成は維持する。

| 項目 | 開く画面 | 引き継ぐ対象 |
| --- | --- | --- |
| 変更をコミット | 対象ファイル・メッセージ・コミット。macOS の差分は別画面へ遷移 | 選択ファイル、または選択フォルダ以下の変更 |
| 差分一覧（macOS）／差分を確認 | ファイル一覧。macOS はファイルを開いて比較へ遷移 | 選択ファイル、または選択フォルダ以下の変更 |
| 履歴を表示 | コミット一覧・説明・変更一覧（macOS）、コミット一覧・詳細（Windows）、グラフテキスト（Linux） | 対象のリポジトリ |
| 変更を受信（Pull） | 対象・リモート・実行・結果 | 現在のブランチと追跡先 |
| 変更を送信（Push） | 対象・リモート・実行・結果 | 現在のブランチと追跡先 |
| リモートを更新（Fetch） | 対象・リモート・実行・結果 | 対象のリポジトリ |
| ブランチを切り替え | 現在のブランチ・切り替え先・実行 | 対象のリポジトリ |
| リポジトリを複製（Clone） | 取得元・親フォルダ・実際の作成先・実行 | 親フォルダの中に取得元のリポジトリ名のフォルダを自動で作る。名前の入力欄は設けない。親フォルダの既存内容は保持する |
| リポジトリの管理（macOS / Windows）／詳細操作 | macOS / Windows は各管理画面の入口。Linux はブランチ管理・変更・マージ | 対象のリポジトリ全体 |

- 背景の右クリックはそのフォルダを対象にする。以前のファイル選択を流用しない。
- Finder の Clone は「この階層に…」でクリックした行の親を保存先にする。「選択フォルダ内に Clone…」は選択フォルダを明示的に指定する。リスト表示で偶然選択した別フォルダへ Clone 先が変わらない。コミットや差分の選択範囲は従来どおり保持する。
- Finder / Nautilus / Dolphin は複数選択を渡す。同じリポジトリ内のみ受け付ける。
- Explorer は単一のファイル・フォルダを対象にする。フォルダを選べば配下の変更をまとめて扱える。
- コミットでは対象の変更を最初から選択。全選択・選択解除と件数を表示する。
- リポジトリ・ブランチ・対象件数を常に明示。選択範囲外の変更をコミットに含めない。
- ファイルの状態は「変更」「新規」「削除」「名前変更」「競合」などの日本語で表示。
- メッセージが空、選択が空、リモートが未設定などの状態では実行できない。
- 送受信は対象を確認して実行する。起動するだけで push / pull は実行しない。
- 進行中と完了・失敗を表示する。完了後は結果を読んで閉じられる。
- 通常の画面にブランチ管理を並べない。macOS / Windows では競合案内から専用画面を開く。
- macOS の通常起動はメニューバーのみ。ようこそ・詳細設定は常駐メニューで選んだときに開く。Git 操作は Finder またはリポジトリ選択後のアプリ画面から開く。「戻る」で親画面へ戻る。Windows の通常起動は「ようこそ」、Linux は操作選択画面。
- macOS / Windows の後続の右クリック操作は既存ウィンドウへ配送する。macOS は元の画面と下書きを保持し、Windows はリポジトリごとのコミット下書きを保持する。Git 処理中の起動要求は待機する。Linux は既存の別ウィンドウ方式。

## 起動契約

各 OS のエントリーポイントは `--action <操作> --path <絶対パス>` を受け付ける。
操作は `open`, `commit`, `diff`, `log`, `pull`, `push`, `fetch`, `switch`, `clone`, `workspace`。
macOS では追加で `init`, `stash`, `tags`, `remotes`, `tools` を受け付ける。機能とプラットフォームごとの対応は [FEATURES.md](FEATURES.md) を参照。
macOS の履歴操作は `cherry-pick`, `revert`, `rebase`, `merge` で各専用画面を直接開ける。
Windows では追加で `stash`, `tags`, `remotes`, `files`, `branches`, `conflicts`, `merge`, `rebase`, `cherry-pick`, `revert`, `identity`, `settings` を受け付ける。Cherry-pick / Revert の画面は履歴から対象を選び、確認して実行する。
`--path` は複数指定可能。`--` 以後もパスとして扱う。旧 `--open <パス>` も利用可能。
Linux では従来の位置引数も利用可能。

Finder は `gitnebula://commit?path=…&path=…` のように操作をホスト名として渡す。
不正な操作名は拒否する。パスをシェル文字列に埋め込まない。
履歴と送受信はリポジトリ全体の操作で、ファイル選択によって履歴を絞り込む仕様ではない。

## 宇宙テーマ

| 要素 | 仕様 |
| --- | --- |
| 背景 | 深宇宙 `#090D1D`。紫と青の淡い星雲、静かな星の装飾 |
| パネル | 不透明な紺 `#12182C`。差分や入力欄の可読性を優先 |
| アクセント | 星雲の紫 `#B39DFF`。主要ボタン・ブランド |
| 主文字 | `#E9EAFA` |
| 補助文字 | `#A5B1CF` |
| エラー・競合 | `#FFBE90` と説明文。色だけで区別しない |
| 用語 | 標準的な Git 操作名と短い日本語の説明。宇宙の比喩を操作名にしない |

OS のファイル選択 UI、フォント、キーボード操作を使う。装飾にアニメーションは不要。
Mac は単一 AppKit ウィンドウ + SwiftUI + Foundation Process、Linux は GTK 4 + Python subprocess、Windows は WPF + .NET Process。
GUI ランタイムは共有しない。

Pull は fast-forward のみ。追跡設定のあるリモートを初期選択し、追跡先のブランチ名を尊重する。
ブランチ削除はマージ済みのみ。削除とマージ中止は確認を求める。
リポジトリ内のテキストをマークアップとして解釈しない。

実装参照: [Finder Sync](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Finder.html)、[Explorer cascading menus](https://learn.microsoft.com/en-us/windows/win32/shell/creating-cascading-menu-handlers)、[Nautilus MenuProvider](https://gnome.pages.gitlab.gnome.org/nautilus-python/class-nautilus-python-menu-provider.html)。
